# ============================================================

# 1. PRODUCT

# ============================================================

Product name:

MAMA

Full name:

Maternal Access, Monitoring & Action

Tagline:

"Speak naturally. Get the right help. Don't repeat yourself."

Core statement:

"Sahara hears Africa. Gemini reasons over what it heard. MAMA turns that understanding into action."

MAMA is a voice-first maternal-health communication, intake, routing, and referral assistant designed for African code-switched speech.

MAMA is NOT an AI doctor.

MAMA is NOT an autonomous diagnostic system.

MAMA is NOT intended to replace healthcare workers.

MAMA's purpose is:

VOICE
→ UNDERSTAND
→ CLARIFY
→ SAFETY CHECK
→ ACTION
→ HUMAN HANDOFF

The key product experience is:

"Don't Repeat Yourself."

A user speaks naturally once.

MAMA converts the conversation into structured information.

MAMA performs an appropriate downstream workflow.

With consent, MAMA creates a structured referral/handoff so the user does not need to repeat the entire story to a healthcare worker.

# ============================================================

# 3. ROLE OF INTRON SAHARA

# ============================================================

Intron Sahara MUST be the primary speech/code-switching layer of MAMA.

Use Sahara for:

* speech recognition;
* African code-switched speech;
* language-pair handling;
* streaming transcription where supported;
* speech-related metadata where available.

Sahara is the core technology differentiator of MAMA.

Do NOT replace Sahara with Gemini for the primary MAMA speech pipeline.

Do NOT build the application so that Sahara is merely mentioned in the README.

Sahara must be integrated into the actual application workflow.

Keep all Sahara credentials server-side.

Use environment variables.

Example:

SAHARA_API_KEY=

Never expose the API key in frontend code.

---

# ============================================================

# 4. ROLE OF GEMINI

# ============================================================

Use Google Gemini as the reasoning/orchestration layer.

Gemini receives the transcript and structured conversation context generated by the application.

Gemini may perform:

* intent classification;
* information extraction;
* missing-information detection;
* conversational reasoning;
* follow-up question generation;
* conversation-state interpretation;
* referral-summary generation;
* natural-language response generation.

Gemini MUST NOT directly execute sensitive application actions.

Gemini should return structured outputs.

Validate all Gemini responses against schemas.

The architecture should look like:

SAHARA
↓
TRANSCRIPT
↓
GEMINI
↓
STRUCTURED OUTPUT
↓
VALIDATION
↓
SAFETY ENGINE
↓
ACTION ENGINE

Do not allow arbitrary LLM text to trigger sensitive workflows.

---

# ============================================================

# 5. ROLE OF NVIDIA / OTHER SPEECH MODELS

# ============================================================

NVIDIA is NOT required to be the main MAMA reasoning model.

NVIDIA may be used as one of the benchmark speech models if an appropriate NVIDIA speech model/API is available.

Alternatively, use another suitable speech model such as Whisper or another eligible model.

The competition requires at least three speech models including:

1. Intron Sahara;
2. Model B;
3. Model C.

Choose Model B and Model C based on:

* availability;
* reliability;
* suitability for speech recognition;
* African/code-switching relevance;
* ability to reproduce results;
* API accessibility.

Possible candidates include:

* NVIDIA speech/ASR;
* Whisper;
* Gemini speech capabilities;
* another eligible commercial/open-source speech model.

Before finalizing the benchmark providers, inspect the available APIs and choose models that can actually be executed.

Do NOT fabricate benchmark results.

# ============================================================

Ask only questions that meaningfully affect the next safe action.

# 13. SAFETY ENGINE

# ============================================================

Implement a deterministic safety engine separate from Gemini.

The safety engine should evaluate structured facts.

Use three routing levels:

ROUTINE

NEEDS_ATTENTION

URGENT

These are routing categories, NOT medical diagnoses.

The safety engine should be conservative.

If critical information is uncertain:

ASK

If the situation may require urgent professional attention:

ESCALATE

If a user requests human help:

HUMAN_HANDOFF

Do not allow Gemini alone to determine dangerous actions.
